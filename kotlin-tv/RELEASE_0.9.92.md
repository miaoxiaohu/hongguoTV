# Kotlin 0.9.92：码是活的，但屏幕上那张会自己作废

<!-- notes -->
上一版把 `Date` 头补上之后，iPhone 是能打开手机输入页了 —— 可用户又报「还是打不开」。
查下来网络从头到尾都是通的：同一个地址，手机打不开，PC 上 `curl` 拿到 200。
真凶是**上一张码的过期定时器**：换过码之后，旧码到点会无条件让电视「换一张新码」，
关掉的却是屏幕正显示的那张 —— 用户手里刚扫的码当场变成死地址。
这一版让过期回调先认身份：只有过期的正是当前这张，才允许换码。
<!-- /notes -->

最低 Android 8.0 / API 26，versionCode 9092。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.91 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、屏幕上那张码会被「上一张码」的过期定时器关掉

**现象**：电视上打开「手机输入」，弹窗里的二维码和地址都在。手机扫码，Safari 报「无法访问此网站」。
同一时刻用 PC `curl` 同一个地址，**200**，页面完整 —— 看起来像手机网络问题。

**取证（2026-11-07 22:30—22:40，小米电视 192.168.1.25）**：

| 时刻 | 事实 |
|---|---|
| 22:31 | 打开「手机输入」，屏幕地址 `…:40897/849c9b9f…` |
| 22:33 | PC `curl` 该地址 → **200**，本机自检正常 |
| 22:35 | 屏幕上换成了另一张码 `…:33347/5075277b…`（这时会话才开了 4 分钟） |
| 22:36 | `curl` 旧地址 `40897` → **连接被拒**；新地址 `33347` → 200 |

会话 TTL 是 30 分钟、过期后还有 10 分钟宽限期（端口留着回一句中文提示）。
4 分钟就换码、而且是**直接关端口**（不是宽限期里的 410），只有一条路径能做到：`expirePhoneSession()`。

**根因**：旧会话不会被新码关掉（这是上一版特意保留的：手机扫到旧码要能看到「已失效」提示），
但它自己的 30 分钟定时器还在跑。定时器一响就回调 `onExpired` → `expirePhoneSession()`，
而那个函数里的 `closeSession()` 关的是 `PhoneSessionPolicy` 里**当前**挂着的会话 —— 也就是刚换上的新码。
于是新码被顶掉、又生成第三张；用户手上那张从此永远连不上。

时间线也对得上：22:05 左右为排查生成过一张码，30 分钟后正好是 22:35 —— 它响的时候，关掉的是 22:31 这张。

**这一版**：

- `PhoneSessionPolicy` 加 `isCurrent()` / `expire(candidate){}`：过期回调先认身份，
  **只有过期的正是当前这张，才允许换码**。别人家的闹钟不许收走你手上的码。
- `deliverPhoneQuery()` 同理：旧码提交的内容照样送到电视，但只有它是当前码时才收掉屏幕上的弹窗。
- 换新码仍然不急着关旧会话（保留宽限期，手机扫到旧码会看到中文提示）—— 单测守着这一条。
- 新增单测：换过码之后，旧码过期**不许**触发换码；当前码过期**必须**触发。

### 二、更正上一版的判断：iPhone 的入站并没有被路由器隔离

上一版「已知限制」里写着「iPhone 到无线设备的入站被路由器按客户端隔离挡掉了，代码侧无解」。
**这个结论是错的**，这一版把它撤回：

- iPhone 与电视同在 MIFI 这台小米 BE36 的 2.4G 上（电视 BSSID `50:4f:3b:ec:50:86`，AP 的 MAC 是 `…:84`，同一台设备）；
- iPhone 醒着时，电视 ping 它是通的（4 个包收到 2 个，RTT 44—120 ms）；
- iPhone 扫新生成的码，Safari 正常打开输入页 —— 0.9.91 和 0.9.92 各验过一次；
- 之前那些「100% 丢包 / ARP FAILED」的观测，都是**手机锁屏进省电**时采的样：
  iOS 锁屏后不回 ARP，看起来就像被隔离。拿 ping 判断 iPhone 的死活不可靠，得让手机真的打开一次页面。

顺带说明这台网络的真实拓扑（之前几轮都猜错了）：`192.168.1.1` 是 x86 的 iStoreOS，**没有无线**；
Wi-Fi 是 `192.168.1.2`（小米 BE36，2.4G `MIFI` / 5G `MIFI_5G`）和 `192.168.1.177`（Redmi AX1800「MIFI-2F」）两台 AP 发的。
两台 AP 的终端 MAC 都学在 iStoreOS 的 `eth2` 上，所以无线终端之间的流量根本不过主路由 —— 主路由上不可能有能拦它的规则。

## 落点

- app `PhoneSessionPolicy.kt`：新增 `isCurrent()`、`expire(candidate, action)`。
- app `TvTools.kt`：`startPhoneSession()` 的过期/提交回调带上会话身份；`deliverPhoneQuery(query, from)` 只在提交的是当前码时才收弹窗。
- app `PhoneSessionPolicyTest.kt`：新增「旧码过期不许动当前码」。

## 验证

**实机（小米电视 192.168.1.25，Android 9 / API 28，0.9.92 本地包，覆盖安装）：**

- `dumpsys package` 回读 `versionCode=9092 / versionName=0.9.92`；
- 连开两次「手机输入」：第一张 `…:35643/…`、第二张 `…:40101/…`，**两张都返回 200**
  （旧码在宽限期里照样能给提示，新码没有被顶掉）；
- 当前码响应头：`HTTP/1.1 200 OK` + `Date: Sat, 07 Nov 2026 14:49:11 GMT` + `Content-Length: 1079`；
- 端到端：iPhone Safari 打开当前码 → 页面正常显示输入框（用户确认）。

**单测：** `:core:test`、`:app:testDebugUnitTest` 全绿。

## 版本号说明

- versionCode 由 CI 从 tag 算（`major*1000000 + minor*1000 + patch`）：tag `kotlin-v0.9.92` → 9092。
- 上一版已发布的是 `kotlin-v0.9.91`（9091），新 tag 必须严格新于所有已发布的 kotlin-v 版本。

## 已知限制

- **别拿 ping 判断 iPhone 的死活**：锁屏时它不回 ARP，电视 / 路由器上看到的都是 `FAILED` 或 100% 丢包，
  但这不代表网络不通。要用就让它真打开一次页面。
- **中文拼音上屏仍未自动验证**：那台 Palm 只有 AOSP LatinIME 与 Gboard，`adb shell input text` 不支持中文，
  ADBKeyboard 在这台 Android 17 上收不到广播。网页侧已按标准声明 `inputmode="text"`，
  需人工在真机键盘上敲一次中文确认。属设备 IME / 自动化环境限制，不是代码问题。
