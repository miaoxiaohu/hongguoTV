# Kotlin 0.9.91：iPhone 上打不开的那个网页，根因找到了

<!-- notes -->
上一版把二维码会话的时长和过期提示都做扎实了，可 iPhone 上那个网页还是打不开 —— 一直转圈到超时，什么线索都没有。
这一版把根因挖出来了：**我们发出去的响应里少了一个 `Date` 头**。
同一台 iPhone 上开两个只差这一个头的服务，一个能打开、一个打不开 —— iOS 的网络库对缺 `Date` 的响应直接判成非法，连页面都不显示。
顺手还修了一个真 bug：电视一开始播放就把手机输入的会话关了，用户扫完码还没输剧名，码就作废了。
<!-- /notes -->

最低 Android 8.0 / API 26，versionCode 9091。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.90 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、iPhone 打不开网页的真正原因：响应缺 `Date` 头

**现象**：电视上打开「手机输入」弹窗，手机扫码打开网页，页面一直转圈到超时。
同一台 iPhone 上访问 PC 上的普通 HTTP 服务却是好的 —— 所以一开始怎么都怀疑不到自己的代码上。

**根因**：RFC 7231 写着「origin server 必须发 `Date` 头」，我们的响应里一个 `Date` 都没有。
curl 不在乎（它自己会补），Android 的 `HttpURLConnection` 也不在乎，
但 **iOS 的网络库（CFNetwork）会把这响应判成非法**，表现就是页面根本不显示，只有一个转圈的图标。

**取证方式（2026-11-07）**：在 PC 上起了六个只改响应头的对照服务，逐个在 iPhone 上打开：

| 服务 | 响应头 | iPhone |
|---|---|---|
| 8893 | 最简头 + IPv6 双栈绑定 | 能打开 |
| 8894 | 最简头 + IPv4 绑定 | 能打开 |
| 8897 | 最简头 | 能打开 |
| 8895 | 电视全套头 **+ `Date`** | **能打开** |
| 8896 | 电视全套头，**缺 `Date`** | **打不开** |
| 8898 | 旧版状态行 `HTTP/1.1 200 Response` | 打不开 |

8895 和 8896 的响应头只差一个 `Date`，结果一个能开一个不能开 —— 这就是判据。

**这一版三处一起改**：

1. **补 `Date` 头**（core `PhoneSearchServer`）。
   格式按 IMF-fixdate：`Sat, 07 Nov 2026 12:44:29 GMT`（日子补零）。
   没用 `DateTimeFormatter.RFC_1123_DATE_TIME` —— 那个格式化器不补零日，`07` 会变成 `7`。
2. **状态行换成标准原因短语**（同一处）。
   以前写死 `"HTTP/1.1 $code Response"`，`Response` 不是标准原因短语（该是 `OK` / `Not Found`）。
   虽然 RFC 允许自定义短语，但严格解析器未必肯收 —— 没必要留着这个风险。
3. **把响应头的顺序也理顺**，并给这两条各补了一条单测锁住。

### 二、电视一开始播放，手机输入的会话就被关掉了

**现象**：用户扫完码，手机上打开网页准备输剧名，电视这时自动续播「接着看」，
用户手机上那个网页就再也连不上了 —— 端口已经关掉，只剩一个转圈的图标。

**根因**：会话和弹窗绑在了一起。
电视开始播放 / 换集时走 `releasePlayer()`，那里调了 `tvTools.close()`；
`close()` 顺手把手机输入的会话也关了 —— 而用户可能正准备输剧名。
更隐蔽的是弹窗的 `onDismiss` 回调：**它是异步的**，
开新二维码时旧弹窗的 dismiss 可能在新会话挂上之后才回调，把刚建好的会话又关掉。

**这一版**：

- 会话的生命周期改跟 **App** 走（退出 App 才结束），不再跟界面上的弹窗走。
  弹窗被收起（关掉、退后台、开播放、换页）一律不碰会话。
- 会话只在这三处关闭：提交过一次、会话过期换码、App 退出。
- 新增 `PhoneSessionPolicy`（app 层）专门管会话归属，并配了单测。
  这一条以前没有测试守着 —— 改回去过一次就复发一次。
- 换新码时**不急着关旧会话**：服务端本来就有宽限期，
  手机扫到旧码会看到一句中文提示，而不是对着一个死地址转圈到超时。

## 落点

- core `PhoneSearchServer.kt`：新增 `reasonPhrase()`；补 `Date` 头；状态行改标准原因短语。
- app `TvTools.kt`：`close()` / `background()` 只收弹窗，不关会话；
  `open()` 的 `onDismiss` 不再 `closeSession()`；会话改由 `PhoneSessionPolicy` 管。
- app `PhoneSessionPolicy.kt`（新增）：会话归属、换码不关旧会话、释放才关。
- core `PhoneSearchServerTest.kt`：新增「状态行是标准原因短语」「响应带 `Date` 头」。
- app `PhoneSessionPolicyTest.kt`（新增）：会话存活、换码不关旧会话、释放才关。

## 验证

**实机（小米电视 192.168.1.25，Android 9 / API 28 / 1920x1080，0.9.91 本地包）：**

- 遥控器走查：搜索页焦点在输入框 → 连按 3 次右键依次到「搜索」「历史」「手机输入」→ 确认弹出二维码弹窗；
- 响应头实测：`HTTP/1.1 200 OK` + `Date: Sat, 07 Nov 2026 12:44:29 GMT`，与在 iPhone 上能打开的对照服务 8895 逐项一致；
- 会话存活：开码 200 → 关掉二维码弹窗 200 → 返回上一页 200 → 进入详情页 200；
- 端到端：`POST /<token>/submit` body `query=love` → 200 → 电视上立刻出结果
  （搜索框显示 love、「站内没有《love》，以下是同类推荐」、「已搜索全库 2400 部」）；
- 同一会话在 Palm 192.168.1.30 上访问也是 200。

**单测：** `:core:test`、`:app:testDebugUnitTest`、`:app:lintRelease` 全绿。

## 版本号说明

- versionCode 由 CI 从 tag 算（`major*1000000 + minor*1000 + patch`）：tag `kotlin-v0.9.91` → 9091。
- 上一版已发布的是 `kotlin-v0.9.90`（9090），新 tag 必须严格新于所有已发布的 kotlin-v 版本。

## 已知限制

- **iPhone 到无线设备的入站仍不通，这跟 App 无关**：<!-- 0.9.92 更正：这条判断是错的，见 RELEASE_0.9.92.md 第二节 -->
  2026-11-07 实测 —— iPhone 能访问 PC（有线网口）上的服务，
  但访问不了 Palm（192.168.1.30）和电视（192.168.1.25）上的服务；
  从 Palm ping iPhone 是 `Destination Host Unreachable`，从电视 ping iPhone 是 100% 丢包，
  而 PC ping iPhone 正常。
  也就是说**这台 iPhone 的入站流量被路由器按客户端隔离挡掉了**，
  有线设备能进，无线设备进不来。
  这一点只能从路由器侧解决（关掉 AP / 客户端隔离，或给 iPhone 换一张允许互访的网），代码侧无解。
- **中文拼音上屏仍未自动验证**：那台 Palm 只有 AOSP LatinIME 与 Gboard，`adb shell input text` 不支持中文，
  ADBKeyboard 在这台 Android 17 上收不到广播。网页侧已按标准声明 `inputmode="text"`，
  需人工在真机键盘上敲一次中文确认。属设备 IME / 自动化环境限制，不是代码问题。
