# Kotlin 0.9.85：左右滑进度不再跟系统返回手势打架

<!-- notes -->
播放页的左右拖进度跟系统返回手势撞车了：从屏幕边缘起手往里滑，进度会拖一半，页面同时又退回去了。这一版把系统手势区（屏幕左右边缘）整个让给系统 —— 边缘起手的滑动一律不接管，系统照常返回；屏幕中间起手的横滑照旧拖进度。是否让位由系统手势区宽度自动判定：三键导航和电视上系统手势区宽度为 0，行为跟以前一模一样，不多一个设置项。
<!-- /notes -->
最低 Android 8.0 / API 26，versionCode 9085。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.84 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、问题的根子

全面屏手势导航的设备上，屏幕左右边缘是系统的**返回手势区**。
0.9.83 加的横滑拖进度没有避开这一块：从边缘起手往里滑，
App 认定这是「拖进度」，系统认定这是「返回上一页」，两件事同时发生 ——
用户看到的是「进度拖了一半，页面又退了」。

实测（2026-11-05，Palm 替身机 192.168.1.30，LineageOS 24 / Android 17，`navigation_mode=2`）：
横屏下系统手势区是左 `[0,0][39,720]`、右 `[1241,0][1280,720]`，各 39 px。

### 二、边缘整个让给系统

判定只看**起手位置**（系统的返回手势也只看起手位置，从中间起手拖到边缘不会触发返回）：

- 起手落在系统手势区里 → App **整轮不接管**，这一轮的事件原样交给系统，系统照常返回上一页，
  进度一点不动。
- 起手在屏幕中间 → 照旧横滑拖进度、纵滑调音量、单击切 HUD、双击播放/暂停。

### 三、是否让位自动判定，不加设置项

让位的依据是**系统手势区的宽度**：

- `ViewCompat.getRootWindowInsets(...)` → `WindowInsetsCompat.Type.systemGestures()` 的左右 inset；
- 每次按下实时读一遍，跟着旋转、跟着用户改手势灵敏度；
- 宽度为 0（三键导航、电视、API 29 以下）就完全不启用，行为与 0.9.84 逐字节一致。

普通 App 读不到 `Settings.Secure.navigation_mode`（那是 shell 权限），所以没有靠它判断，
也就没有为「系统明明没有返回手势却还是让掉了边缘」这种情形单开设置项。

### 四、实现落点

- core 新增 `SystemGestureEdge`（纯 Kotlin，可单测）：只回答「这一次按下是不是起手在系统手势区里」。
- app 层 `PlayerTouchController`：`ACTION_DOWN` 先判 HUD 按钮（优先级更高），再判系统手势区；
  命中就整轮放行，中途不改判。
- `MainActivity`：只加了一处读 inset 的代码，`dispatchKeyEvent` **一行没动** —— 遥控器零回归。

## 验证

- **core 单测**：全绿。新增 `SystemGestureEdgeTest` 8 个用例：左右边缘命中、中间不命中、
  inset 为 0 一律不命中、负数 inset 按没有处理、边界点不算命中、宽度未知不拦、
  手势区过宽时最多让出一半屏。
- **`:app:lintDebug`**：无 error。
- **Palm 实机（0.9.85 / 9085，覆盖安装 9084 成功）**：

  | 项 | 判据 | 结果 |
  |---|---|---|
  | 左边缘起手横滑 | 播放位置不变 | 00:39 → 00:39 ✅ |
  | 右边缘起手横滑 | 播放位置不变 | 00:39 → 00:39 ✅ |
  | 中间起手右滑 | 位置前移 | 00:39 → 01:55（+76 s）✅ |
  | 中间起手左滑 | 位置后退 | 01:55 → 00:39（−76 s）✅ |
  | 纵滑 | STREAM_MUSIC 音量 | 15 → 6（−9 档）✅ |
  | 单击 | HUD 显隐 | dump 2768 → 805 → 2768 ✅ |
  | 遥控器 23 | 播放/暂停 | PLAYING ↔ PAUSED ✅ |
  | 遥控器 22 | 快进 | 01:17 → 01:47（3 次 × 10 s）✅ |
  | 遥控器 20 | 选集面板 | 打开 ✅ |
  | 遥控器 4 | 收起面板 | 回到播放页 ✅ |

  对照组：同一台机器上的 0.9.84，左边缘起手横滑把进度从 00:39 拖到 02:53 ——
  这正是用户撞上的那一幕。

## 还没有做的

- **系统返回手势本身没法用脚本验**：`adb input swipe` 注入的事件不触发系统手势（系统按真实触摸流判定），
  所以「边缘起手 → 系统真的退回上一页」这一条必须用手指在实机上试。
  App 侧的行为（不抢、不拖进度）已经验过。
- **电视上还没装这一版**：投影的推装服务当前不响应 `/api/info`，服务没起来的时候推装只会表现成「上传失败」。
- **没有打 tag**：CI 从 tag 算 versionCode，`kotlin-v0.9.85` → 9085。
  推 tag 前记得再查一遍已发布版本（`gh release list --repo miaoxiaohu/hongguoTV`）。
