# Kotlin 0.9.51：弹幕的大小和行数可以自己调，搜索也修好了

<!-- notes -->
弹幕的大小和行数现在可以自己调了：设置里能改，正在播的时候也能改，改完立刻生效。
搜索修好了：站内搜索恢复可用，索引里没有的剧也搜得到。
站方搜索临时取不到时，搜索照样出结果，并且会说明结果来自本机索引，不会再说「站内没有《X》」。
<!-- /notes -->

最低 Android 8.0 / API 26，versionCode 9051。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.50 并保留本机收藏、观看记录和设置。

发布页：[kotlin-v0.9.51](https://github.com/miaoxiaohu/hongguoTV/releases/tag/kotlin-v0.9.51)，安装包 `hongguotv-kotlin-0.9.51-android8.apk`。

## 这一版改了什么

- **弹幕的大小和行数可以自己调**：0.9.50 把弹幕做出来了，这一版把它交到用户手里 —— 四档字号、五档行数，正在播的时候改完立刻生效。
- **搜索修好了**：站方 2026-10-22 把搜索页改成纯前端渲染，旧的那条路取不到数据了。换成站方自己的 JSON 接口之后，索引之外的剧重新搜得到。

0.9.50 的弹幕本体、弹幕开关、倍速下弹幕的行为都还在，沿用同一套发布签名，直接覆盖安装即可。

## 弹幕的大小和行数

- **字号四档**：小 / 标准 / 大 / 特大。存的是**档位**不是倍数 —— 倍数是相对「按屏高算出来的基准字号」
  而言的，换台电视同一个倍数看起来完全不是一回事，存倍数等于把「多大」记成了「相对于这台电视多大」。
- **行数**：自动 / 3 / 5 / 8 / 12 行。自动是按屏幕高度算，填满画面上半，下面留给字幕和 HUD。
- **两个旋钮互相独立**：「小字多行」和「大字少行」都能要到。字号、行高、行数是一起算的
  （字大了行就高，能塞下的行就少），算式在 core 里，不依赖 Android，所以能在本机测。
- **改完立刻生效**，不用退出播放再进来 —— 正在看的时候觉得字小，正是最想调它的时候。
  改了字号要重排轨道：不重排的话字变大了还是按老的行高摆，上一行的字会压到下一行头上。
- **设置 → 播放里能改**，播放中的「播放设置」里也能改，正在看的时候不用跑回设置页。
- **屏幕放不下就说出来**：塞不下那么多行时按能放下的算，并明确告诉用户「实际显示 7 行」。
  界面上写着 12 行而屏幕上只有 7 行，用户只会以为这个设置是坏的。
- **跟着本机记录走**：备份里带着这两个字段；老备份（没有这两个字段的）读出来是标准字号、自动行数 ——
  备份是给人拿去用的，不是让人丢设置的。

## 搜索

- **站方把搜索页改成纯前端渲染了**（2026-10-22 实测）：`/search/关键词` 的 HTML 里不再有
  `_ROUTER_DATA` 数据块 —— 首页、分类页、榜单页、**详情页**都还在，**只有搜索页变了**。
  三个不同关键词返回的页面**字节完全相同**（37 KB，MD5 一致），连关键词本身都不在 HTML 里。
- **数据搬到了它自己的接口上**：`GET /api/search/result?query={关键词}`。
  **参数名是 `query`，不是 `keyword`** —— 用 `keyword` 回 400，用 `query` 才回 200。
  这个路径写在搜索页壳页面的内联脚本里（`_SdkGlueInit` 的 `bdms.paths.include`）。
  字段形状和当年 SSR 那份一模一样（`searchList[].video_data.*`），所以解析照旧；
  这个接口还能翻页（请求参数是 `page`，响应里是 `pageNum`/`totalPages`/`hasMore`）。
- **站方自己的 App 签名接口仍然是死的**：`reading/bookapi/search/tab/v/` GET/POST 都回 0 字节（被拒），
  而同一进程里的对照接口 `video_model` 回 23 KB `code=0` —— 所以不是网络问题，也不是签名问题。
  走官网这条路才是活路。
- **那十行是补位，不是搜索的主体**：搜索的主体是本机索引（2400 部都在里面，分类页仍能走查）。
  站方这一路取不到时，搜索照常出结果，并说明结果来自本机索引 ——
  **可选的补位不能拖垮主路径**。（此前它一失败，整页就变成「暂时无法加载」，
  哪怕本机索引里已经有一千多条命中。）
- **不说「站内没有《X》」**：站方这一路取不到的时候，我们根本没问到站方，不能替它下结论。
  这时候页面说的是「站方搜索暂时不可用」，而不是「没有找到相关剧」—— 后者是把本机索引的
  结论冒充站方的结论，那部剧可能真的存在。
- **站上约有 45 万部剧，本机索引只有 2400 部**：站方的 sitemap（28 个文件，每个一万多条
  `/detail?series_id=`）说明全量远大于分类页暴露的那些。索引覆盖不到的剧只有站方搜索找得到，
  所以这一路一断，索引外的剧就一起搜不到了 —— 《亲姐是末世女主,我才是苟王》就是这么消失的。

## 验证记录

- `:core:test` 与 `:app:testDebugUnitTest` 全绿（core 243 项、app 51 项），`:app:lintRelease` 0 错误。
- **弹幕大小和行数这一轮新增 13 项**（排版算式 8 项 + 备份往返 3 项 + 本机记录 2 项），同样做了变异验证：
  把字号档位忽略掉，8 项里 3 项变红；把用户要的行数一律按「能放下的」算，8 项里 1 项变红；
  把「被屏幕截过」永远当成没截，8 项里 1 项变红。
  第一轮「字大了行数变少」那条**没红** —— 它没区分「变少」和「全一样」，字号整个不起作用时它照样绿着。已改严。
- **搜索这一轮新增 4 项**（接口路径与参数名 / 站方失败不拖垮搜索 / 站方失败时不谎称「站内没有」/
  站方正常时不误报），变异验证（三个都在最终这一棵树上重跑过）：把「取不到就算了」改回「取不到就整页失败」，
  `ContentRepositoryTest` 69 项里 2 项变红；把「站方失败」的标记永远按没失败报，69 项里 2 项变红；
  把参数名从 `query` 改回 `keyword`，69 项里 1 项变红。
- **用真实站点验过**（2026-10-22，走出货代码本身）：
  搜「苟王」—— 站方 10 条，**第一条就是《亲姐是末世女主,我才是苟王》**（`series_id` 7692443906679507993，
  126 集），`matched=1`，所以界面不会说「站内没有《苟王》」。
  搜「都市」—— 站方 0 条（页面改成前端渲染后那一路一度全灭），本机索引 2400 部完好，命中 1039 条，
  第 1 页 30 条，`hasMore=true`。
- **已在实际投影仪上完成覆盖安装**：本机用发布签名出包，改动全部装在电视上，
  推到推装服务并装上（服务把文件存成了 `app-release-7.apk`，队列里回读 `installed: true`）。
  `firstInstallAt` 没变 → 覆盖安装，本机的全库索引和记录都保留。
- **签名是同一张证书**：本机出包的证书 SHA-256 `4f4cf502…`，与发布脚本里写死的 `RELEASE_CERT`
  一字不差 —— 所以这一版盖得住用户从发布页下载的 0.9.50，不会变成「要先卸载」。
- **一个只在真机上才会炸的坑**：`app` 模块把 `org.json` 依赖排除了，运行时用的是 Android 自带的那份，
  它没有 `JSONArray(Collection)` 构造器。core 自己编译和跑单测时用的是 `org.json:json`，有 ——
  所以编译通过、单测全绿，到电视上才会 `NoSuchMethodError`。已改成只用 `put` 往里塞。

## 已知边界

- 弹幕是**每一集**自己的，不是整部剧连起来的。
- 拉不到弹幕时什么都不显示，也不会在屏幕上留一条错误 —— 弹幕是锦上添花，不该打断播放。
- 弹幕文本里混着平台自己拼进去的 `[昵称]` 标记，目前原样显示。
- 投影仪上的**实际画面效果**还需要人眼过一遍：字号和行数现在能自己调了，但**哪一档看着舒服**
  仍然得站在投影仪前面才知道 —— 本机量过的是数值（字号、行高、几行），不是观感。
- 搜索仍然只问站方第一页：主体是本机索引，站方那一路目前只取第一页的十条。
- 站方的搜索接口随时可能再变一次（今天就变过一次）。变了也不怕：App 仍然能搜，
  靠本机索引那一半，只是少了站方那十行，并且会明说结果来自哪里。
