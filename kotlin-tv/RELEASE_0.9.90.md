# Kotlin 0.9.90：手机输入的二维码不会「悄悄失效」了

<!-- notes -->
上一版让遥控器能走到「手机输入」按钮了，可走查时又发现一个更难受的问题：二维码开着开着就不好使了 ——
会话只有 5 分钟，手机上打开网页却一直转圈到超时，屏幕上什么线索都不留，用户根本不知道是「码过期了」还是「网不通」。
这一版把会话拉长到 30 分钟，过期后电视上自动换一张新码，手机扫到过期的码会看到一句中文提示（而不是对着没人监听的端口转圈）。
另外 0.9.89 有个修漏的地方：搜索框的按键监听装在了「有搜索结果」的判断之后，用户刚打开搜索页、还没输词的时候，右键仍然到不了工具条按钮。
<!-- /notes -->

最低 Android 8.0 / API 26，versionCode 9090。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.89 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、二维码过期后不再「静默失效」

**现象**：电视上打开「手机输入」弹窗，手机扫码打开网页。等一会儿再提交，页面一直转圈到超时；
电视屏幕上还是那张旧二维码，看不出任何异常。用户既不知道是码过期了，也没法判断是不是网络问题。

**根因**：会话 TTL 只有 5 分钟（`PhoneSearchServer` 的 `ttlMillis=300_000`），到期后 `serve()` 循环退出、
Socket 直接关掉。端口一关，手机浏览器就连到了一个没人监听的地址 —— 只有等 TCP 超时才知道连不上，
**拿不到任何原因**。而且电视这边的回调 `onExpired` 只是把弹窗内容换成「二维码已过期，请关闭后重新打开」，
用户得自己记住刚才搜过什么、回到搜索页再找一次按钮。

**这一版三处一起改**：

1. **会话时长 5 分钟 → 30 分钟**（`DEFAULT_TTL_MILLIS=1_800_000L`）。
   掏手机、开浏览器、输剧名，常常正好踩在 5 分钟的边上，30 分钟才够用。
2. **过期之后端口再留 10 分钟宽限期**（`GRACE_MILLIS=600_000L`）。
   这段时间里访问旧码拿到的是 **HTTP 410 + 中文提示**，不是超时：
   - 会话过期 → 「二维码已失效，请在电视上重新打开「手机输入」。」
   - 码已提交过一次 → 「这个二维码已经用过了，请在电视上重新打开「手机输入」。」
3. **电视上自动换新码**（`TvTools.expirePhoneSession()`）。
   会话到期时立刻在原位置生成一张新二维码，手机什么时候扫都有效，用户不用自己重新找按钮。
   电视在后台时不弹新窗口（免得在后台弹一个看不见的对话框），只把服务重建好，等回到前台再摆出来。

### 二、0.9.89 修漏了：刚打开搜索页时，右键还是到不了工具条

0.9.89 把搜索框的按键监听从「有搜索结果」块里挪了出来，但**安装语句本身还在 `displayed.isEmpty()` 的提前 `return` 之后** ——
搜索页刚打开、还没输词的时候，那段代码根本走不到，监听器压根没装上，右键仍旧到不了「搜索 / 历史 / 手机输入」。

这一版把监听器的安装**提到空结果分支之前**，并把「结果第一条」用 `var firstSearchCard` 往下传。
「右」的落点改成候选链：焦点图算出来的右邻居 → 「搜索」按钮 → 工具条整体，
挨个试，谁 `requestFocus()` 成功算谁的；「下」在没有结果时不抢焦点，交给系统处理。

## 落点

- core `PhoneSearchServer.kt`：新增 `companion object`（TTL 30 分钟 / 宽限 10 分钟）、`hardDeadline`、
  `expiredNotified` 去重通知；会话过期后端口继续服务并回 410 + 中文提示；网页文案改「最长 30 分钟」。
- app `TvTools.kt`：抽出 `phoneAddress()` / `startPhoneSession(owner, content, address)`；
  `expirePhoneSession()` 改为自动换新会话 / 新二维码；弹窗文案改「会话最长 30 分钟，过期会自动换一张新码」。
- app `MainActivity.kt`：搜索框方向键监听器的安装提到 `displayed.isEmpty()` 分支之前；
  右键落点改候选链；无结果时不下抢焦点。
- core `PhoneSearchServerTest.kt`：拆分 `a closed session is unreachable`；
  新增「过期会回一句中文提示而不是死端口」「默认会话时长 30 分钟」。

## 验证

**实机（小米电视 192.168.1.25，Android 9 / API 28 / 1920x1080，0.9.90 包）：**

- 遥控器走查：搜索页焦点在输入框 → 连按 3 次右键依次到「搜索」「历史」「手机输入」→ 确认打开二维码弹窗；
- 新会话 `http://192.168.1.25:41873/<token>`：GET 200，页面含 `name="query"`、`inputmode="text"`、文案含「30 分钟」；
- 端到端：`POST /<token>/submit` body `query=love` → 200 → 电视上立刻出结果
  （搜索框显示 love、「站内没有《love》，以下是同类推荐」、「已搜索全库 2400 部」）；
- 会话存活：前台 200 → 按 HOME 退后台 → 200 → 回前台 → 200（0.9.88 的修复未退化）。

**单测：** `:core:test` 与 `:app:testDebugUnitTest` 全绿。

## 版本号说明

- versionCode 由 CI 从 tag 算（`major*1000000 + minor*1000 + patch`）：tag `kotlin-v0.9.90` → 9090。
- 上一版已发布的是 `kotlin-v0.9.89`（9089），新 tag 必须严格新于所有已发布的 kotlin-v 版本。

## 已知限制

- **iPhone 上打不开这个网页**：2026-11-07 走查时发现，iPhone 用 Chrome 访问局域网 `http://` 地址打不开，
  但**同一台 iPhone 访问 PC 上对照服务 `http://192.168.1.11:8899/` 同样超时** —— 而该服务在本机 curl 是 200，
  同一网段的 PC 与另一台 Android 手机访问电视会话也都是 200。
  也就是说被挡下的是**iPhone 这一侧的局域网 http 访问**，不是电视 App 的服务。
  判定为客户端 / 浏览器侧限制（iOS 的本地网络权限、Chrome 的「始终使用安全连接」把 http 升级成 https），
  **代码侧无解**：自签 https 证书在 iOS 上要手动信任描述文件，不可行。
- **中文拼音上屏仍未自动验证**：那台 Palm 只有 AOSP LatinIME 与 Gboard，`adb shell input text` 不支持中文，
  ADBKeyboard 在这台 Android 17 上收不到广播。网页侧已按标准声明 `inputmode="text"`，
  需人工在真机键盘上敲一次中文确认。属设备 IME / 自动化环境限制，不是代码问题。
