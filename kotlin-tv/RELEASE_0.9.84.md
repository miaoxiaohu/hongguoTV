最低 Android 8.0 / API 26，versionCode 9084。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.83 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、播放接口重新带上签名

站方把 `novel/player/multi_video_model/v1/` 的规矩改了两次，这次是第二次：

- 2026-10-27：接口不再认「现编的设备身份」，只认平台注册过的身份；请求**不许**带签名头。
- 2026-11-02：接口**又**要签名了。带注册身份但不带签名的请求，被回成 HTTP 200 + **0 字节**。

0 字节是这里最难认的一种失败：状态码正常，目录页、搜索页、详情页全都好好的，只有「播放」哑掉，
而公开播放页那一条退路只会给 10 秒试看片段（`hongguoduanju.com/video/public/<id>/360p.mp4`，约 1.2MB）。
所以从外面看就是「每集只能看 10 秒然后播放失败」，很容易被当成网络问题或者片源问题。

现在的请求形态（core `ContentRepository.registeredStream`）：

- **注册身份**：照旧走平台自己的 `device_register`，拿 `device_id` / `iid`。
- **六个签名头**：`X-Argus` / `X-Gorgon` / `X-Medusa` / `X-Khronos` / `X-Ladon` / `X-Helios`，
  由既有的 `Signer.sign` 生成，签名覆盖 query 和时间戳。
- **query 带时间戳**：`ts`（秒）与 `_rticket`（毫秒），由 `Signer.encode` 一起生成。

### 二、一个身份只能问一次地址，用过就扔

实测（2026-11-05）：同一个注册身份连续问十次，**第一次成功、其余九次全部回空体**；
重新注册一个身份，第二次立刻就答了。也就是说站方把「注册身份」当成一次性门票。

所以身份改成**用一次就扔**：`takePlaybackIdentity()` 取出身份后立刻把缓存清掉，
拿到空体就重新注册再来一轮（`signedPlaybackWithFreshIdentity`，最多两轮）。
代价是每一集多一次注册请求，换来的是不再「第一集能看、后面全看不了」。

### 三、主域空体就换备用域

`api5-normal-sinfonlineb.fqnovel.com` 对这个客户端回空体，换到 `api5-normal-hl.fqnovel.com`
就带完整答案（HTTP 200 / 24406 字节 / `code=0`，`data[vid].video_model`，跟原来的解析路径一致）。

两个域**各自签名**（签名覆盖 query，一个域的签名不能拿去另一个域用），空体就换域重发；
主机表在 `ContentRepository.PLAYBACK_HOSTS`，主域仍然排在前面 ——
站方哪天不再挑这个客户端，第一个就能用上。

### 四、验证

- **core 单测**：全绿。改写后的六个用例按新行为断言（请求带签名头、每集重新注册、
  公开页 404 / 空体 / 503 各自的措辞都对得上）。
- **端到端探针**：`--play=real-drama` **成功 8 / 失败 0**，全部 1080P，每部真读 1048576 字节；
  `--play=comic-drama` 成功 7 / 失败 1（唯一失败是站方那一集自己回 HTTP 500）。
- **Palm 实机**：0.9.84 覆盖安装成功，第 9 集播完自动连播到第 10 集 ——
  完整剧集才连得起来，10 秒试看片段放不到第 9 集去。

## 还没有做的

- **电视上还没装这一版**：投影的推装服务（192.168.1.26）当前不响应 `/api/info`，
  服务没起来的时候推装只会表现成「上传失败」。等推装服务开了再推，或者直接从 APK 装。
- **没有打 tag**：CI 从 tag 算 versionCode，`kotlin-v0.9.84` → 9084。
  推 tag 前记得再查一遍已发布版本（`gh release list --repo miaoxiaohu/hongguoTV`）。
