# 红果 TV 原生独立版

这是独立的 **Kotlin + Android 原生 View + Media3** 工程，最低 Android 8.0 / API 26。安装一个 APK，联网后可直接浏览和播放，无需部署 Node、Docker 或填写服务器地址。

- 应用名称：红果TV+
- 包名：`com.hongguotv.nativeapp`，与上游 RN 版 `com.hongguotv`（显示名「红果 TV」）**包名不同，可在同一台电视上同时安装共存**。两者图标也不同：本项目为珊瑚色电视屏矢量图，上游仍是 RN 模板的默认 Android 机器人。
- 收藏和历史独立保存在本机，不自动迁移旧版数据。
- APK 不含 JNI 库，可由 Android 在 ARM32、ARM64、x86、x86_64 上运行；视频解码能力依赖设备。
- 源码分支：`main`。
- [下载正式签名 APK](https://github.com/miaoxiaohu/hongguoTV/releases/latest)（仓库已公开，匿名可下载）

全部版本的变更说明按版本倒序列在 [CHANGELOG.md](CHANGELOG.md)。

## 0.9.70 修复

- **站方改了取址的规矩，现在换个身份就能取到全部剧集**：2026-10-27 起，站方播放取址端点虽然还在、HTTP 200，但**带签名 + 现造一个临时身份**的请求一律返回空体；不签名又没有注册身份时返回 `{"Code":110001}`。真实做法是两步：先注册一个匿名设备换到正式身份，再拿这个身份**不带任何签名头**去取址，地址就回来了 —— 1000 集剧抽第 1/4/50/100/500/1000 集全部 1080P，跨剧 7 部各抽首/中/末 **21/21 全通**。
- **降级顺序是三道门**：注册身份 + 无签名 → 旧签名接口（保留，站方若恢复就还能用）→ 公开网页页（只有前 3 集 360p，只当兜底）。
- **顺手修掉一个「假绿」**：注册响应里**没有状态字段**，原实现把「字段缺失」当成「状态非 0」，于是每次注册成功都被自己误杀 → 回落签名路径 → 再回落公开页 → 只剩前 3 集 360p。现在无状态字段按成功处理。

## 0.9.69 修复

- **切到「正在准备」的那一集时，地址不再重问一遍**：自动连播会在后台备好下一集的地址和开头 1 MB。以前这时按下播放，取值的 `take()` 会把槽位版本号推高，**已经问到的地址当场作废**，备集随即被取消，播放器再从零问一遍（12 个并发 × 最多 2 波）。结果是首页「继续观看」直接按、详情页立刻按这两条最快的路径上，预取等于没做，而且取消前它还在跟画面抢同一条上行。现在备集一拿到地址就交出来，切集时先取走、再取消；密钥带集号，不会拿到上一集的地址。
- **页面那份备集不再没人管**：进详情页会先备上那一集。以前它只在「按下播放」和「销毁 Activity」时停，按返回、退后台、内存吃紧时还在拉到 60 秒预算满，并在 10 分钟 TTL 内占着 1 MB。现在这三种情况都会取消。
- **预热前缀读过去就释放**：那 1 MB 读完就不再挂着。

## 0.9.52 修复

- **自动连播不再抢画面的带宽**：准备下一集原来在画面一出现就开始干，而那时播放器自己的缓冲还没填满 —— 预取的那 1 MB 和画面抢同一条上行。现在等缓冲填到位再动手（门槛从 3 秒提到 15 秒，对齐播放器自己的缓冲目标）。
- **准备有了自己的期限**：预取用的客户端命中之后就是这一集自己的传输客户端，原来那套紧超时会让慢一点的这一集先超时。现在超时放宽，另有一个 60 秒的看门狗管准备 —— 到点就放弃，不拿本集的带宽再试第二次第三次。
- **长关键词也能搜**：站方的搜索接口只收 30 个字（实测超了回 400 `invalid_query`），而客户端原来放行到 80 个字，所以长关键词必然失败。现在截到前 30 个字去问，本机索引也认「剧名是这几个字的开头」这种形状，所以剧名后面多打了几个字照样搜得到。截断了界面会说一声。
- **「暂时不可用」和「用不了」分开了**：站方回 5xx 是等一等就好，站方拒绝查询或换了形状是等不来的。以前一律说「暂时」，把永久失败说成了暂时。

逐条说明见 [0.9.52 发布说明](RELEASE_0.9.52.md) —— 那是发版时所用的同一份文档，电视上「检查更新」弹出来的短说明也出自它。站方搜索接口这一轮的整轮实测见 [站方搜索接口实测](../docs/research/2026-10-23-hongguo-search-api.md)。

## 0.9.51 修复

- **弹幕的大小和行数可以自己调**：四档字号（小 / 标准 / 大 / 特大）、五档行数（自动 / 3 / 5 / 8 / 12）。设置里能改，正在播的时候从「播放设置」里也能改，改完立刻生效 —— 不用退出播放再进来。
- **屏幕放不下就说出来**：界面上写着 12 行而屏幕上只有 7 行，用户只会以为这个设置是坏的。所以塞不下时按能放下的算，并明确告诉用户「实际显示 7 行」。
- **搜索修好了**：站方 2026-10-22 把搜索页改成纯前端渲染，旧的那条路取不到数据了（三个不同关键词返回的页面字节完全相同）。现在走站方自己的 JSON 接口（`GET /api/search/result?query=`），索引之外的剧重新搜得到 —— 《亲姐是末世女主,我才是苟王》就是这一类。
- **站方搜索取不到时不再整页报错**：搜索的主体是本机索引，站方那十条只是补位。取不到就照常用本机索引出结果，并且说明结果来自哪里。此前它一失败，整页就变成「暂时无法加载」。
- **不再说「站内没有《X》」**：没问到站方就不能替它下结论。那种情况下页面说的是「站方搜索暂时不可用」。

## 0.9.49 修复

- **落点按位置算，不再按「第几个」算**：原来每个页面各手写一套 `nextFocus*Id`，同一个动作在不同页面落到不同的地方 —— 首页从「首页」按下键，焦点跳到屏幕**最右边**的片库按钮；搜索页从「手机输入」按下键，焦点落到**最左边**的第一张卡。现在统一成两条规则：左右在同一行内走到最近的一个（到头在本行内绕回另一头），上下按横向位置对齐到相邻行。
- **按方向键不会再卡住**：网格第一列按左、最后一列按右，原来方向键被指回自己 —— 按了没反应，焦点卡在原地。
- **选集面板第一行按「上」不再按下标分派**：以前 0—2 去「上一组」、3—4 去「下一组」，纯数下标数出来的。
- **详情页的季度卡遥控器走得到**：剧集网格末行的「下」不再靠系统猜。
- **输入框的左右键留给输入框**：输入框里按左右是移动光标，不是移动焦点。

## 0.9.48 修复

- **首页（热门）的页码能跳了**：在首页按页码，弹框一直说「只有一页，没有可挑的」—— 而首页明明有 34 页，屏幕上的「上一页 / 下一页」也明明是通的。算总页数的那段判断里没有首页这一支，于是首页永远答「一页」。首页的页数只能来自站方（实测 2026-10-20：三条货架都是 800 部、24 条一页、34 页），现在这个数从 core 一路带上来。
- **首页的页码那行字会写总数**：此前只写「第 2 页」，现在写「第 2 / 34 页」。
- **「还有下一页」和「一共有几页」是同一个数**：此前一个说「还有」、一个说「一共」，两个数各算各的，页码选择器能翻到的最后一页和「下一页」按到底的那一页会打起来。
- **页数算成一份**：页数和页码那行字原本是两个并排的 `when`，条件一样、写法一样，漏掉一支就是漏掉两支 —— 首页就是这样，两处同时漏，屏幕上写着「第 2 页」，选择器却说「只有一页」。现在一份算法算出两个答案，并配了回归测试。

## 0.7.0 新增

- **首页更紧凑**：焦点预览固定为一行剧名和一行状态，完整简介留在详情。接着看、收藏有更新各显示最多 8 部，稍后看、热门各最多 10 部；超过后从行末「查看全部」进入集合。本地收藏、最近观看及首页集合每页最多 20 部，避免一次创建全部剧卡。首屏数量不改变本机记录的保存上限。
- **快捷操作保持位置**：收藏、稍后看和隐藏更新当前卡片区域，不重建整个页面；保留每行横向位置，移除当前卡后聚焦相邻卡。返回列表保留页码，并确保恢复的焦点处于可见区域。
- **本机查询不再反复解析记录**：启动在后台载入收藏、历史、设置及首页缓存，之后通过内存索引查询；记录按变更字段合并，由后台串行写入。首页缓存独立存储，兼容迁移旧版记录，生命周期变化会请求及时写入。
- **封面和请求可以取消**：图片按实际显示尺寸采样和裁切，优先处理焦点附近内容；图片等待队列最多 24 项，低内存设备使用 1 个图片线程和 4 MiB 内存缓存，其他设备为 2 个线程和 8 MiB。保留 24 MiB 封面磁盘缓存；离开页面、换集或进入后台时释放旧图片绑定并取消相应请求，翻页与搜索也会取消前一次内容请求。
- **换集复用播放器**：普通换集复用 Media3 播放器与播放视图，更新媒体源和本集监听；故障恢复、退出和后台释放仍走完整清理。播放进度与媒体状态按可见性、播放状态和事件更新，减少后台或隐藏界面的重复工作。
- **预加载靠近片尾**：按当前倍速估算剩余播放时间，在最后 30 秒内且自动连播、网络和缓冲条件允许时准备下一集；每集最多尝试 3 次，尝试间隔至少 15 秒。仍只保留一个结果和最多 1 MiB 开头数据，2 分钟失效，取消及失败走普通加载流程。
- **避免只播声音却黑屏**：过滤已知不兼容的视频格式；优先遵守默认清晰度，若只有更高清晰度可用则显示「兼容资源」。视频轨道无法播放时显示失败操作，不把音频 READY 当成视频成功。
- **续播少一层操作**：最近观看和首页续播确认后直接播放，退出回原列表；播放中「↓」直接选集，「↑ / 菜单键」打开更多操作。选集取消恢复原播放或暂停状态。

## 0.5.0 新增

- 定时停止：播放菜单选择 15 / 30 / 60 / 90 分钟后停止，或本集 / 再播完 3 / 5 集后停止。到点暂停、保存进度并取消自动重试，片尾先判断定时再自动连播。分钟按实际经过时间计时（包含暂停），集数在片尾计数，手动切集不扣次数。仅本次观看有效，退出播放器或切到后台会取消。

## 0.4.0 新增

- 播放故障恢复：网络恢复后重新获取播放地址，保留集数、位置和暂停状态；同一集最多自动重试 3 次，可立即重试、停止自动重试或改用 720P。退到后台或退出播放会取消重试；解码类错误不反复进行网络重试。

- 首页一键续播：显示最近 3 部未手动标为整剧已看的剧，直接确认续播；已播完一集则优先接着下一集。按剧集 ID 匹配进度，避免片源调整顺序后串集。
- 收藏更新提示：前台打开应用自动检查超过一小时未检查的收藏，收藏页可手动检查；逐部读取最新详情，显示新增集数和当前总集数。首次检查建立基准，进入详情后清除该剧新增提示；失败保留之前结果，连续失败 3 部时停止本轮检查。提示基于内容接口实际集数，不提供后台推送或平台账号同步。
- 全局默认配置：设置中选择 480P / 720P / 1080P，以及 0.75 / 1 / 1.25 / 1.5 / 1.75 / 2×；对所有剧集生效，重启保留。清晰度为优先上限，具体取片源提供的档位；播放菜单内修改清晰度或倍速也保存为全局默认。

## 使用

1. 从 [发布页](https://github.com/miaoxiaohu/hongguoTV/releases/latest) 下载最新正式 APK，首次拷贝到电视安装，或通过 `adb install -r APK文件路径` 覆盖安装。之后可在设置 → 版本与更新中检查更新（需仓库为公开）。
2. 在电视应用列表打开「红果TV+」，进入首页或搜索。
3. 首页续播和最近观看确认即播放；发现新剧时确认进入详情，选择开始观看。设置中可选择 480P / 720P / 1080P 上限和是否自动连播。

播放中：确认键暂停/播放；左右跳转 10 秒，长按连续跳转；向下直接打开选集，向上或菜单键打开播放、上下集、倍速等更多操作。返回键先关闭选集或收起进度条与菜单，再退出播放；从列表直接续播时回原列表，从详情开始播放时回详情。列表恢复原卡片和页码。

## 构建

需要 JDK 17、Android SDK Platform 36 / Build Tools 36.0.0。Gradle 8.14.3 包装器已包含；不需要 npm、Node 或 React Native。设置 `ANDROID_HOME`，或在本目录的 `local.properties` 写入 `sdk.dir=SDK绝对路径`。

```sh
# 仓库根目录：开发包直接可安装，无需发布私钥
./kotlin-tv/gradlew -p kotlin-tv :core:test :app:lintDebug :app:assembleDebug
adb install -r kotlin-tv/app/build/outputs/apk/debug/app-debug.apk
```

正式 APK 使用独立发布密钥，**私钥和口令不在 GitHub 中**。重建发布包时，配置以下环境变量，或创建被 Git 忽略的 `kotlin-tv/keystore.properties`：

```properties
storeFile=/absolute/path/to/your-release.jks
storePassword=your-password
keyAlias=your-alias
keyPassword=your-password
```

对应环境变量：`HONGGUOTV_KEYSTORE`、`HONGGUOTV_STORE_PASSWORD`、`HONGGUOTV_KEY_ALIAS`、`HONGGUOTV_KEY_PASSWORD`。使用自己的签名重建时，不能直接覆盖安装官方发布密钥签名的 APK；卸载会清除本机记录。更新已安装的正式版应继续使用同一发布密钥。

```sh
./scripts/build-kotlin.sh
# 输出：out/hongguotv-kotlin-<versionName>-android8.apk
```

电视上装的是同一个推装服务（电视本机 10000 端口）时，也可以直接推过去：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\push-to-tv.ps1 `
  -Apk out\hongguotv-kotlin-<versionName>-android8.apk -WaitSeconds 180
```

脚本会先探活服务、再上传、再请求安装，并**等电视上真的装完、读回版本号变了**才算成功 ——
「推了」不等于「装上了」。推装服务的 key 由服务自己在 `/api/info` 里给出，脚本自动取，
不再有写死在仓库里的默认值；也可以用 `-Key` 显式指定。

产物文件名里的 `<versionName>` 取自 `HONGGUOTV_VERSION_NAME`，未设置时从
`kotlin-tv/app/build.gradle.kts` 的默认值 `0.0.0-dev` 读取，versionCode 为 1。
默认值**故意远低于任何已发布版本**：应用按 versionCode 严格递增判断更新，本地包
若带着高于线上的版本号，电视会认为「已是最新」而永远不再提示。
复现某个线上版本请传入该 release `update.json` 里的两个值：

```sh
HONGGUOTV_VERSION_CODE=9010 HONGGUOTV_VERSION_NAME=0.9.10 ./scripts/build-kotlin.sh
```

## 工程结构

- `core/`：纯 Kotlin 内容列表、搜索、详情、请求签名、播放地址解析、MP4 索引和分段处理；可在 JVM 测试。
- `app/`：原生电视界面、遥控器焦点、本地收藏/进度、Media3 播放器及自定义 DataSource。
- `core/src/test/`：固定签名对照、NIST AES-CTR 向量、跨样本/非对齐分段、AVC 索引恢复及畸形输入校验。
- `tools/signing-oracle.cjs`：仅开发期生成兼容性测试样本；运行、构建 APK 不需要它。

播放器直接通过 HTTPS 分段拉取数据，经本机 Kotlin 处理后交给 Media3。没有 JS 引擎或常驻内容服务。仅在用户打开「手机输入」或「手机备份与恢复」窗口时，APK 临时监听局域网 HTTP；最长 5 分钟，窗口关闭或应用进入后台后停止。备份下载每次二维码一次，上传成功后关闭会话并等待电视确认。页面不处理平台账号凭据或媒体。媒体只在内存中处理，不下载整部剧到存储。元数据响应、封面大小、索引数量和播放缓冲均有上限。

```sh
# 可选联网检查：真实网站和内容接口，网络变化可能导致失败
./kotlin-tv/gradlew -p kotlin-tv :core:run
# 漫剧分类、搜索两页、详情与真实视频分段检查
./kotlin-tv/gradlew -p kotlin-tv :core:run --args=--comic
# 漫剧排行榜首两页及末页：来源名次、热度、分页和重复检查
./kotlin-tv/gradlew -p kotlin-tv :core:run --args=--ranking
# 重新生成签名对照样本才需要 Node
node kotlin-tv/tools/signing-oracle.cjs
```
