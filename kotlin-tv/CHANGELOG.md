# 发布记录

按版本倒序。每个版本只留一句话和一处链接，**完整的变更、测量与验证在各自的 `RELEASE_<版本>.md` 里** —— 那份文件同时是 GitHub 发布页的正文，标签一推 CI 就按它出包。

电视「检查更新」弹窗里那句短说明，取自每份 `RELEASE_<版本>.md` 中 `<!-- notes -->` 与 `<!-- /notes -->` 之间的块，改文件别动标记。

## 0.9.70 · 站方改了取址规矩，这次换个身份就能拿到全部剧集

站方把播放取址的规矩改了：旧的「带签名 + 现造一个临时身份」不再被接受。0.9.70 改成先用一次匿名设备注册换一个正式身份，再拿这个身份不带签名去取址 —— 整部剧都能取到地址，不再只剩前 3 集。旧签名那条路留作后备。→ [完整说明](RELEASE_0.9.70.md)

- 状态：2026-10-28 按 tag `kotlin-v0.9.70` 由 CI 出包发布，CI 的测试、lint 与签名校验全绿；线上包 versionCode 回读 9070。Palm 手机实机复验 0.9.70 正式包：冷启动进首页 → 点海报 → 连续切集，第 68–73 集全部出首帧，取址全部落在 1080p，零解析失败、零播放失败。**电视上的播放对照数据还没取到** —— 验证时电视（192.168.1.26）不可达。

## 0.9.69 · 备好的那一集，按下播放时不再被自己丢掉

切到「正在准备」的那一集时，已经问好的播放地址不再作废，按播放直接接着用；离开详情页、退后台、内存吃紧时后台准备立刻停下；那 1 MB 预热前缀读过去就释放。→ [完整说明](RELEASE_0.9.69.md)

- 状态：2026-10-27 按 tag `kotlin-v0.9.69` 由 CI 出包发布，CI 的测试、lint 与签名校验全绿；电视上的播放对照数据还没取到。

## 0.9.68 · 播放接口偶尔拒答时，不再冤枉「这部剧只有 3 集」

站方接口空回不再被当成「这一集不存在」，改成换设备身份重新签名再问，最多 6 次、4 秒以内；地址改为 IPv4 优先、IPv6 兜底。→ [完整说明](RELEASE_0.9.68.md)

- 状态：已被 0.9.69 取代。2026-10-27 补推到电视，回读 9068；电视上的播放效果未实测。

## 发一个新版本时

1. 建 `kotlin-tv/RELEASE_<版本号>.md`，标题写在第一行，`<!-- notes -->` 块写电视弹窗那句话。**少了这个文件，CI 只会告警并给电视推一句通用说明**，不会中断出包。
2. 本文件顶部加一条（一句话 + 链接），并把它下面那条的「当前线上最新版」挪过来。
3. 推 tag `kotlin-v<版本号>`，CI 会用 `kotlin-tv/RELEASE_<版本号>.md` 作为发布页正文，并从中抽 `notes` 块写进 `update.json`。

发布证书由 `scripts/publish-tv-update.py` 的 `RELEASE_CERT` 在发布时断言，不在文档里维护；换证书会让老用户无法就地升级。
