# Kotlin 0.9.88：手机上能真正打字了，电视切后台也不再被拒连接

<!-- notes -->
上一版修完搜索页的焦点落点之后，手机输入还有两个问题：手机上打开网页打不了字，提交时电视上还会弹「连接被拒绝」。这一版把两个根因都挖出来了：网页输入框没声明文字键盘，浏览器拿原生气泡挡在提交前面；电视一退到后台就把手机输入的小服务关掉了，页面能开、提交却已经没人接。改完以后：手机点输入框就弹文字键盘，回车键上写着「发送」；电视退到后台再回来，手机输入的会话还活着。
<!-- /notes -->

最低 Android 8.0 / API 26，versionCode 9088。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.86 / 0.9.87 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、手机上打不了字：输入框没告诉手机「这是文字键盘」

原来的输入框只有 `type="text"` 和 `required`。两个问题叠在一起：

- 手机浏览器**不一定**给它弹文字键盘（没声明 `inputmode`），用户看到的是没法输入的框；
- `required` 会让浏览器在提交前弹自己的原生气泡（英文「请填写此字段」），把中文提示的提交按钮挡在后面 —— 用户只看到气泡，根本不知道下一步该干什么。

这一版给输入框补齐了手机键盘需要的声明：

- `inputmode="text"` + `enterkeyhint="send"` —— 明确要文字键盘，回车键上显示「发送」；
- `autofocus` —— 打开页面自动聚焦，不用先点一下；
- `autocapitalize="off" autocorrect="off" spellcheck="false" autocomplete="off"` —— 剧名是专有名词，不要自动大写、不要被自动纠错改掉；
- `maxlength="80"` 与服务器校验一致；
- **去掉 `required`** —— 空提交交给服务器回中文提示（「请输入 1—80 个字符的剧名」），不再让英文原生气泡抢戏。

提示文案也改成人话：「点下面的输入框，用手机键盘输入剧名，再点「发送到电视」」。

### 二、提交时 ERR_CONNECTION_REFUSED：电视退后台就把服务关了

这是实测抓出来的，不是猜的。同一段会话：

- App 在前台时，对那个 URL `curl GET` 返回 **200**；
- 按 HOME 把 App 退到后台后，再对同一个 URL `curl GET` 返回 **000 / exit 7**（连接被拒）。

浏览器里的表现正好对得上：**页面能开**（GET 早到，会话还活着），**提交却失败**（POST 晚到，会话已经死了）。

根因在 `MainActivity.onStop()` → `tvTools.close()` → 把手机输入的 ServerSocket 关了。电视端 App 退后台是常态（切别的 App、息屏、弹通知），用户拿起手机点「发送」时服务已经没了。

这一版把「关会话」和「收界面」拆开：

- 退后台只**收弹窗、保留会话**（`TvTools.background()`）—— 服务继续在后台应答，手机提交照样通；
- 回前台再把二维码弹窗**重摆**出来（`TvTools.foreground()`），会话还在就重新显示，过期了才作废；
- 会话本身最长 **5 分钟**，超时才真正关闭（`expirePhoneSession()`）；
- 后台收到的查询词**先记着**（`pendingPhoneQuery`），回前台再执行搜索 —— 电视上看到的是「刚发来的那个词」的结果，不是回到首页再自己搜一遍。

没有加前台服务，也没有开机自启 —— 按用户的要求，这版不引入任何常驻进程。

### 三、附带：搜索页按下键落在第一条

上一版 0.9.87 未发布，这一版一起并进来。搜索页的工具条（输入框 + 搜索 / 历史 / 手机输入 / 续建索引）往下，焦点一律落在**结果列表的第一条**，不再按屏幕几何对齐落到中间那一列。

- 根因：焦点图默认按几何对齐落点 —— 从「搜索」按钮往下落到第五张卡，从输入框往下落到第二张。
  搜索结果对用户是一份列表，入口就该是第一条。
- 修法：焦点图支持把「往下」的落点钉死（`FocusPlan.build` 的 `downOverrides`），搜索页把整条工具条
  钉到当前页第一张卡。
- 附带修掉两个既有缺陷（实机走查时发现的，不是本次改动引入的）：
  - 网格里的卡片按「上」出不了结果区 —— 焦点图给的上方目标在 ScrollView 之外，系统的焦点搜索
    跨不过去（ScrollView 把方向键当滚动吃掉了）。卡片上另有按键兜底，跨出滚动区时手动移焦点。
  - 输入框按「上」「下」都不动 —— EditText 自己处理方向键。输入框改为接管：下 = 结果第一条，
    上 = 「搜索」页签。

## 落点

- core `PhoneSearchServer.kt`：页面 HTML 的输入框声明；POST 校验不变（空输入回中文提示）。
- app `TvTools.kt`：`background()` / `foreground()` / `closeSession()` / `deliverPhoneQuery()` /
  `expirePhoneSession()` / `renderPhoneCode()`。
- app `MainActivity.kt`：`pendingPhoneQuery` + `submitPhoneQuery()`；`onStop()` 改走 `background()`；
  `onResume()` 负责重摆弹窗并补搜后台收到的词。
- app `Focus.kt` / `FocusRouter.kt`：搜索页焦点落点钉到第一条。

## 验证

**实机（Palm 192.168.1.30，0.9.87-dbg 包）：**

- 会话存活：App 退到后台后，对同一个 URL 重新 `curl GET` 仍返回 **200**（修复前是连接被拒）。
- 端到端：打开电视给的 URL → 页面正常渲染 → 输入框自动聚焦（`autofocus` 生效）、无 `required` 拦截 →
  填入 `love` → 点「发送到电视」→ 页面变为「已发送到电视 / 请回到电视查看搜索结果」；
  切回电视，搜索框里是 `love`，页面显示「站内没有《love》，以下是同类推荐」「已搜索全库 2906 部」，推荐列表已出。
- 抓包佐证：`tcpdump` 抓到 `POST /<token>/submit` 确实到达服务端（不是前端假成功）。

**单测：** `core` 全绿，新增 `PhoneSearchServerTest` 断言「页面向手机要文字键盘，且把空值校验交给服务器」；
`FocusTest` 四条新断言。

## 已知限制（设备环境导致，不是代码问题）

- **中文拼音上屏没能在 Palm 上自动验证**：这台机只有 AOSP LatinIME 与 Gboard，`adb shell input text` 不支持中文，
  ADBKeyboard 在这台 Android 17 上收不到广播注不进文本。网页侧已按标准声明 `inputmode="text"`，
  需要人工在真机键盘上敲一次中文确认。
- **LineageOS Jelly 浏览器里网页表单打不进字**：Jelly 把所有按键输入都导向自己的地址栏（实测字符进了地址栏，
  网页 input 为空），这是浏览器自身的按键分发行为，网页侧改不了。端到端验证是用 Chromium 内核浏览器做的。
- 电视端没有 adb over network、推装服务常年掉线，电视上的升级仍需用户配合（先 `GET /api/info` 探活）。

## 版本号说明

- 0.9.87 / versionCode 9087 已被实验包 `0.9.87-dbg` 占用。实验包必须**严格小于**正式版，
  否则电视上收不到正式版更新提示，所以正式版取 **0.9.88 / versionCode 9088**。
- versionCode 由 CI 从 tag 算（`major*1000000 + minor*1000 + patch`）：tag `kotlin-v0.9.88` → 9088。
  本地手工出包必须用同样的数，且出包前先删 `app/build`。
