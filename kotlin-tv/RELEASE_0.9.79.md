# Kotlin 0.9.79：弹幕从右边第一个字出来，左最后一个字结束

<!-- notes -->
弹幕的横向运动改了：一条弹幕整条先待在屏幕右边外面，飞进来时**第一个字**从屏幕右缘露头，飞出去时**最后一个字**在屏幕左缘收尾 —— 不会再整条一下子摆在右边。同时去掉了「弹幕只飘在画面那一块矩形里」的限制，飞行区间改回整屏宽度。
<!-- /notes -->
最低 Android 8.0 / API 26，versionCode 9079。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.77 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、弹幕横向运动的几何

用户的要求是：「弹幕应该是从右边第一个字出来，左最后一个字结束」。

- **飞行区间是整个屏幕**，不再是「视频画面那一块矩形」。算式挪进 core 的 `DanmakuMotion`
  （`xAt` / `visibleTextRange`），app 层只负责用：
  `x = 屏宽 - (已飞时间/全程) * (屏宽 + 文字宽度)`。
- **起止都放在屏外**：刚起步时整条弹幕在屏幕右边外面，一个字都看不见；飞进来时第一个字从
  **屏幕右缘**露头；飞出去时最后一个字在**屏幕左缘**收尾。整条都在屏外时干脆不画。
- **推翻了 0.9.50 的「弹幕跟画面矩形走」**（`git show 3eecda9`）。那一版画的时候没有裁剪，
  起点落在画面右缘，文字整条画在右边那条黑边上 —— 一出场就整条可见，正是用户说的
  「整条突然出现在右边」。竖屏短剧在 16:9 电视上左右留黑边时，毛病尤其明显。
- **竖向一律不动**：轨道、字号、行数、同屏条数、透明度、晚到重锚定，全都还是原样。

### 二、随之而来的一个可见变化

竖屏内容在 16:9 电视上左右有黑边，而飞行区间现在是整屏 —— 所以弹幕会**从黑边上飞过去**，
不再只待在画面那一块里。这是「从右边第一个字出来」这个要求的直接结果：弹幕现在能碰到屏幕的
右缘和左缘，而不是停在画面的边缘。

### 三、交付里不留诊断代码

实机取证用的临时探针（`DanmakuProbe`：纯黑底 + 合成弹幕 + 探针自带时钟）已从 app 源码里
撤掉，正式包重新构建、重新安装验证过。

## 验证记录

- **单测**：`:core:test` **347 条 0 failures**（新增 `DanmakuMotionTest` 9 条在内：起手整条在
  屏外 / 收尾整条在屏外 / 只往左飞 / **第一个字先露头、最后一个字收尾** / 飞行盖满整屏 /
  中途整条可见 / 进场只露头几字 / 出场只剩最后一个字 / 退化输入安全）。
  `:app:testDebugUnitTest`、`:app:lintRelease`、`:app:assembleRelease` 全过。
- **Palm 手机实机（0.9.78-dbg / 9078）**，像素级测量（合成弹幕「甲乙丙丁戊己庚辛」，纯黑底，
  录屏 40 秒后逐帧量亮像素的 x 范围），三次完整飞行结果一致：
  - **进场**：第一个亮起来的帧只有屏幕**最右缘 1~2 列**（x=1279）；稍后一点，右缘露出的是
    **甲乙**（最前面两个字）；
  - **中途**：整条 8 个字完整可见（x=935~1278）；
  - **出场**：最后一个还亮的帧只剩屏幕**最左缘 2~4 列**（x=0~3）；稍早一点，左边剩下的是
    **庚辛**（最后两个字）。
  - 即：**第一个字从右边出来、最后一个字在左边结束**，与用户的要求一致。

## 已知边界

- **电视端还没实测**。投影上的推装服务（`192.168.1.26:10000`）在验证期间是离线的，要用户
  手动打开才能推；电视没有 adb over network，电视上的行为只能人眼看。Palm 上验过的是同一份代码。
- 电视上竖屏内容会有弹幕飘过左右黑边（见「二」），这是本次要求的直接结果。
- 0.9.77 的两处待用户目视验收仍未回音：设置页「弹幕设置」摘要是否折行、面板按返回是否闪退。
- **本次只做了本地提交**，没有推 tag、没有发 Release。

## 发布状态

- **产物**：`kotlin-tv/app/build/outputs/apk/release/app-release.apk`（本机构建，签名与已发布包
  同一张证书，可覆盖安装）。复现构建请设 `HONGGUOTV_VERSION_CODE=9079` 与
  `HONGGUOTV_VERSION_NAME=0.9.79`。
- **本机出包有个坑**：AGP 的 `GenerateBuildConfig` **不跟踪版本号**。不带版本环境变量编过一次
  之后，再带变量编会被判成 UP-TO-DATE，dex 里留下的是上一次的版本号。所以本地出包前必须先删掉
  `app/build/generated/source/buildConfig` 再带变量构建，并回读生成的 `BuildConfig.java` 核对版本号。
- **CI 出包**：推 tag `kotlin-v0.9.79` 后由 CI 出包发布（版本号、签名证书、附件完整性都由 CI
  校验），本文件就是发布页正文，电视更新弹窗的短说明出自 `<!-- notes -->` 块。
- 上一版的记录见 [0.9.77 发布说明](RELEASE_0.9.77.md)。
