# Kotlin 0.9.64：预加载不再等「按播放」那一刻

<!-- notes -->
预加载提前了：用户马上要看的那一集，在首页和详情页上就已经把地址和首包备好，按播放不用再从头问一遍地址、等一遍首包。冷启动从 4.5 秒降到 1.6 秒左右。下一集的预取也改成走同一个热连接池，每集少一次握手。
<!-- /notes -->
最低 Android 8.0 / API 26，versionCode 9064。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.62 并保留本机收藏、观看记录和设置。

## 这一版改了什么

- **用户马上要看的那一集，在页面上就备好**。首页「接着看」那一集、详情页刚打开时焦点所在的那一集，都会在你还在页面上的时候去问地址、拉首包、预热 1MB。按播放的时候，地址和首包都已经在手上了。
- **备集和「下一集预取」分成两份，互不取消**。原来两者共用一个取消口：按下播放会把还在备的那一份一起杀掉，于是按播放永远等不到它。
- **地址和首包都走仓库那个客户端**。每集另起一个客户端看着干净，实则每集都要重新和 CDN 握一次手；仓库那个客户端的连接池是热的。
- **计费网络不备**。那一兆和那一次地址查询，在用户还没说要播之前是白花的。

## 怎么量的

替身手机（Palm PVG100，Android 8.1，192.168.1.30）上装同版本对照，1080P，弹幕开着。每一项都取自应用自己的日志。

**改之前（0.9.62）：**

| 环节 | 耗时 |
|---|---|
| 冷启动首帧（三次） | **4538 / 3302 / 2798 ms** |
| 　其中问地址 | 987 / 1843 / 777 ms |
| 　其中拉首包+解索引 | 767 / 447 / 598 ms |
| 　其中播放器自己 | 约 2800 / 1000 / 1400 ms |
| 下一集预取（问地址+预热 1MB） | 1.5 ~ 1.9 s |
| 切集首帧（预取命中） | 520 ms |

**改之后（0.9.64）：**

| 环节 | 耗时 |
|---|---|
| 冷启动首帧（备集命中，两次） | **1578 / 1876 ms** |
| 　其中问地址+拉首包 | 0（提前做掉了） |
| 　其中播放器自己 | 约 1400 / 1700 ms |
| 备集里问地址 | 654 / 5788 / 10890 ms（站方接口抖动很大） |
| 备集里拉首包 | 833 / 1181 / 1181 ms |
| 下一集预取（改走共享连接池） | 1.48 s |
| 切集首帧（预取命中） | **447 ms** |

**看下来最要紧的一条：问地址本身在 0.45 秒到 11 秒之间抖。** 预取机器不慢（1.5 秒就备好一集），慢的是「按播放才开始问」——把问地址和拉首包挪到按播放之前，冷启动就只剩下的播放器的活。

## 干净版（0.9.64，撤掉全部埋点之后）的复测

上面那些数字是在带读数的实验版（0.9.63-dbg）上量的。正式版撤掉埋点后，在同一台替身手机上重跑三轮冷启动，每轮都是「启动 → 首页就绪 → 按下接着看」：

| 轮次 | 首页就绪 | 备集 | 按播放到首帧 |
|---|---|---|---|
| 1 | 887 ms | 备成 | **2202 ms**（`preloaded=true`） |
| 2 | 885 ms | 备成 | **1915 ms**（`preloaded=true`） |
| 3 | 910 ms | 没备成 | **3148 ms**（`preloaded=false`，走的老路） |

第 3 轮备集没备成，是因为那一刻站方接口自己在抖 —— 同一时间从电脑上直接 `GET https://hongguoduanju.com/` 也要 30 秒才断开（连接被关闭）。那不是应用侧的事。

这一轮同时把「自动连播」也量了：本集结束到下一集首帧 **1990 ms**（这一集只剩 10 秒就播完，预取按 8 秒门槛刚要动手就来不及了），另外一轮站方正在抖的时候是 **11923 ms**。备集命中时自动切集仍然是 **447 ms**。

## 已知边界

- **从片尾续播（这一集只剩几秒）仍然赶不上预取**。预取要本集播满 8 秒才动手（见 `PrefetchPolicy.SETTLE_MS`），剩下不足十秒的一集，切集仍是 1.7 秒左右。这条没有改：门槛一降，用户还没看两秒就跳走的那份备集就白花了。
- **问地址的抖动没有变小，只是挪出了关键路径**。站方那个接口自己慢的时候（实测到 11 秒），备集自己也会慢，只是那时候画面还没开始播。
- **切集那 447 ms 没再往下压**。它花在播放器自己身上：`stop()` + `clearMediaItems()` 之后重新 `prepare()`，解码器和索引都要重建。要再压就得把下一集提前排进播放列表（`player.addMediaSource`），那是播放状态机的改动，这一版没做。
- 备集一次是 1MB 流量加一次地址查询。计费网络不备；看完一整部的「下一集」也不备（下一集的地址得先有分集表才知道）。
