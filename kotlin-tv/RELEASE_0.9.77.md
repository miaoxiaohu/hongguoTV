# Kotlin 0.9.77：弹幕五项并成一个面板，播放失败也不再自己跟自己较劲

<!-- notes -->
弹幕的开关、大小、行数、数量、透明度这五项合并成了一个「弹幕设置」面板：设置页和播放中各留一个入口，选完当场生效，面板不关。另一头修掉了「播放总是重试」——取址失败、注册未成功、只取到 10 秒样片这三种情况现在分开说人话，自动重试封顶 3 次后给出「立即重试 / 尝试 720P / 返回选集」，不再自己跟自己较劲。
<!-- /notes -->
最低 Android 8.0 / API 26，versionCode 9077。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.74 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、弹幕设置合并成一个面板

之前弹幕的五个开关散在设置页左列（弹幕开关 / 弹幕大小 / 弹幕行数 / 弹幕数量 / 弹幕透明度），每项各自弹一次选择器，改完一个想看下一个就得关掉重开。现在合并成**一项**：

- **设置页左列**（从上到下）：默认清晰度 / 默认倍速 / 画面模式 / 自动连播 / **弹幕设置 · 开 · 标准 · 自动 · 中 · 半透明**。右边那一行是摘要，一行放得下。
- **播放中的 HUD**：更多 → 播放设置 → 第 6 项「弹幕设置 …」，进去是同一个面板。
- **面板里五行**：弹幕开关 / 弹幕大小 / 弹幕行数 / 弹幕数量 / 弹幕透明度。选中哪一行按确认，候选**就地竖排展开**（上下走，左右留在原地）；选完立刻生效，**面板不关**，五项的当前值一直都在眼前 —— 正在播的时候觉得字小，正是最想调它的时候。
- **档位一个没少**：大小 4 档（小 / 标准 / 大 / 特大）、行数 5 档（自动 / 3 / 5 / 8 / 12）、数量 3 档（同屏 6 / 12 / 24 条）、透明度 3 档（不透明 / 半透明 / 淡）。
- 面板高度上限是**屏高的 90%**，放不下就在面板内部滚动，不裁切。

### 二、播放「总是重试」

根因链是这么串起来的（每一环都有实测证据）：

1. 取址的死线是 10 秒，超了就报错；
2. 注册失败被一个 **60 秒**的窗口挡着 —— 这 60 秒内再怎么重试都白问；
3. 于是回落链落到**公开网页门**；
4. 网页门给的不是整集，是一段**正好 10.000 秒的样片**；
5. 播 10 秒报错 → 自动重试 → 回到第 3 步 → **一直重试**。

现在：

- **样片按容器时长判定**（时长落在 1～12 秒之间就判定为试看片段并拒掉），不再靠「是哪个门」这种间接线索；
- **注册不可用有独立异常和独立窗口**：窗口从 60 秒缩到 5 秒，而且**从失败那一刻起算**（不是从上一次注册起算）；
- **回落链遇到「注册不可用」或「网络已经死了」不再走网页门** —— 那扇门只会让等待翻倍，不会带来能播的地址；
- **注册换连接重试只对「停顿」生效**，对「连不上」不生效；
- **自动重试封顶 3 次**，之后给出「立即重试 / 尝试 720P / 返回选集 / 停止自动重试」这些能立刻动手的按钮，不再自己跟自己较劲；
- **失败原因和倒计时分两行**：原因（取址超时 / 注册未成功 / 只取到样片 / 网络断了）是「为什么」，倒计时是「现在在干嘛」，倒计时**不许把原因盖掉**。

### 三、关面板必闪退（实机抓到的 BLOCKER，本版已修）

0.9.76-dbg 在 Palm 上抓到：打开弹幕面板后按返回，**必闪退**。

```
java.lang.IllegalStateException: This ViewTreeObserver is not alive
    at android.view.ViewTreeObserver.removeOnGlobalLayoutListener
    at DanmakuSettingsDialog.notifyClosed(...)
    at DanmakuSettingsDialog.onDismiss(...)
```

根因：对话框还没挂到窗口上时，`decor.viewTreeObserver` 拿到的是**浮动观察者**；挂上去之后平台会把监听器 `merge()` 到**根观察者**，同时把浮动观察者 `kill()` 掉。代码却还拿着那个已经死掉的浮动观察者去摘监听器 → `checkIsAlive()` 直接抛异常。

修法：布局回调里重新取一次根观察者；摘除前把「记下来的那个」和「当前 decor 的那个」两个候选都过一遍 `isAlive` 才动手；`dismiss()` 无条件补一次关闭通知（幂等，不会重复）。

### 四、交付里不留诊断代码

临时探针全部撤干净：app 层的上报器（`TvProbe`）、core 层的 `probeDoors` / `probeWebStream` / `StreamInfo.door` / `registeredStreamWith` 拆分，以及 `Probe` 的 `--doors` / `--doorprobe` / `--register` / `--sample` / `--ranges` / `--qualityurls` 六个临时分支。

每日源解析检测要用的 `--play=real-drama` / `--play=comic-drama` **保留**，那不是探针，是常设的巡检。

  - 设置页左列确认只剩 5 项，摘要一行放得下；

  - 候选展开时按返回 → **只收候选，面板不关**，再按一次才关；

  - 「弹幕行数」5 个候选，第 5 个「12 行」能**滚进可视区**；

  - HUD「播放设置」列表第 6 项 =「弹幕设置 开 · 特大 · 12 行 · 多 · 半透明」，选中后打开的是同一个五行面板；

## 已知边界

- **电视端还没实测**。投影上的推装服务（`192.168.1.26:10000`）在验证期间是离线的，要用户手动打开才能推；电视没有 adb over network，电视上的行为只能人眼看。Palm 上验过的是同一份代码。
- **Palm 上有一集 1080P 取不到地址**：点「尝试 720P」能正常播（这正好是那个按钮该干的活）。同一时刻本机探针 8/8 全通、Palm 到 CDN 的 DNS 与 ping 都正常 → 判为**站方对不同出口的间歇性拒绝**，不是这一版的代码问题。
- **弹幕面板在电视上的实际高度与折行取决于 density**，而电视的 `wm density` 取不到。设计上按「密度 ≥320dpi 也要安全」做：面板高度封顶 90%、超出内部滚动、候选竖排展开。若电视上出现摘要折行，把摘要拆成按钮下一行小字即可。
- `(it.scale*100).toInt()` 的截断问题**没有根治**：当前四档（75 / 100 / 130 / 170）精确，改成 `roundToInt()` 属于语义变更，另立项。
- **本次只做了本地提交**，没有推 tag、没有发 Release。

## 发布状态

- **产物**：`kotlin-tv/app/build/outputs/apk/release/app-release.apk`（本机构建，签名与已发布包同一张证书，可覆盖安装）。复现构建请设 `HONGGUOTV_VERSION_CODE=9077` 与 `HONGGUOTV_VERSION_NAME=0.9.77`。
- **本机出包有个坑**：AGP 的 `GenerateBuildConfig` **不跟踪版本号**。不带版本环境变量编过一次之后，再带变量编会被判成 UP-TO-DATE，dex 里留下的是上一次的 `0.0.0-dev`。所以本地出包前必须先删掉 `app/build/generated/source/buildConfig` 再带变量构建，并回读生成的 `BuildConfig.java` 核对版本号。CI 是全新 checkout，不受影响。
- **CI 出包**：推 tag `kotlin-v0.9.77` 后由 CI 出包发布（版本号、签名证书、附件完整性都由 CI 校验），本文件就是发布页正文，电视更新弹窗的短说明出自 `<!-- notes -->` 块。
