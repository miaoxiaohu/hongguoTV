# Kotlin 0.9.89：遥控器终于能走到「手机输入」按钮了

<!-- notes -->
上一版把手机输入的会话和手机键盘都修好了，可真机走查时发现按钮根本走不到：焦点停在搜索框上按右键，焦点纹丝不动 —— 搜索框把方向键当成挪光标自己吃掉了。于是「搜索 / 历史 / 手机输入」这三个按钮在遥控器上永远到不了，手机输入等于废了一半。这一版让搜索框自己接管方向键：右 = 走到工具条第一个按钮，下 = 结果第一条，上 = 回到「搜索」页签。另外上一版没有搜索结果时会把按键监听整个撤掉，现在没结果也能走到按钮。
<!-- /notes -->

最低 Android 8.0 / API 26，versionCode 9089。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.88 及更早版本并保留本机收藏、观看记录和设置。

## 这一版改了什么

### 一、搜索框把方向键当挪光标吃掉，「手机输入」按钮走不到

小米电视（192.168.1.25，Android 9）上实测：焦点停在搜索框时按**右键**，焦点纹丝不动。

根因是 Android 的 `EditText` 把 `DPAD_RIGHT` 当成「移动文本光标」自己处理掉了，根本不往外派发，
焦点系统也就没机会换到右边的控件。上一版已经在搜索框上接管过「下」「上」，**「右」漏了** ——
结果就是工具条上「搜索 / 历史 / 手机输入 / 续建索引」这一排按钮，**用遥控器永远走不到**。

这一版把「右」也接管了：

- 右 = 焦点图算出来的右邻居（工具条第一个按钮）；算不出来就退回「搜索」按钮；
- 下 = 结果列表第一条（没有结果时不动作，交给系统）；
- 上 = 回到「搜索」页签（不按几何落到靠右的别的页签）。

### 二、没有搜索结果时，工具条按钮也走不到

上一版为了避免「钉死的落点指向一张已经不存在的卡」，在没有搜索结果时把搜索框的按键监听**整个撤掉**。

这个撤得太狠了：用户刚打开搜索页、还没输词的时候，右键同样走不到「手机输入」按钮 —— 
而这恰恰是手机输入**唯一**的入口。这一版把「清落点」和「撤监听」拆开：

- 没有结果时只清掉钉死的落点（`downOverrides` 清空）；
- 按键监听**留着**，右 / 下 / 上 照旧；
- 「下」在没有结果时不抢焦点，交给系统处理。

## 落点

- app `MainActivity.kt`：搜索框的 `setOnKeyListener` 新增 `DPAD_RIGHT` 分支；监听器挂载从
  「有搜索结果」块里挪到 `TAB_SEARCH` 块内，与结果有无解耦。
- app `FocusTest.kt`：新增 `theSearchInputCanReachTheToolButtons` —— 断言输入框 →「搜索」→「历史」→「手机输入」的右邻链。

## 验证

**实机（小米电视 192.168.1.25，Android 9 / API 28 / 1920x1080）：**

- 焦点在搜索框时按右键 → 焦点落到「搜索」按钮；再按右键依次走到「历史」「手机输入」；
- 焦点在「手机输入」上按确认 → 二维码弹窗正常弹出（此前用遥控器走不到，只能靠触屏 tap）；
- 搜索结果页：焦点在搜索框按下键 → 落到结果第一条（0.9.88 的行为未退化）。

**单测：** `:app:testDebugUnitTest` 全绿（新增右邻链断言）。

## 版本号说明

- versionCode 由 CI 从 tag 算（`major*1000000 + minor*1000 + patch`）：tag `kotlin-v0.9.89` → 9089。
- 上一版已发布的是 `kotlin-v0.9.88`（9088），新 tag 必须严格新于所有已发布的 kotlin-v 版本。

## 已知限制

- **中文拼音上屏仍未自动验证**：那台 Palm 只有 AOSP LatinIME 与 Gboard，`adb shell input text` 不支持中文，
  ADBKeyboard 在这台 Android 17 上收不到广播。网页侧已按标准声明 `inputmode="text"`，
  需人工在真机键盘上敲一次中文确认。属设备 IME/自动化环境限制，不是代码问题。
