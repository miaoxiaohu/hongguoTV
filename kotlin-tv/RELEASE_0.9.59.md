# Kotlin 0.9.59：首页海报不再被压成一条线

<!-- notes -->
首页的剧海报恢复成完整竖版 —— 之前有一条货架的海报被压成几像素高的一条线，剧名直接压在图上。
矮屏（720p）上顶部的大标题收紧了一点，把竖向空间让给海报。
<!-- /notes -->

最低 Android 8.0 / API 26，versionCode 9059。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.58 并保留本机收藏、观看记录和设置。

## 这一版改了什么

- **首页货架的海报不再被压扁**。海报高度改成按卡片自己的宽度算竖版比例（`TvStyle.POSTER_ASPECT`），不再跟着屏幕剩下的高度缩水。屏不够高时这一排放不下，页面往下滚 —— 海报保持竖版比例，比压成横条好看。
- **海报高度不再用「还没量出来的宽度」来算**。这是海报变成一条线的直接原因，见下一节。
- **矮屏上顶部的大标题收紧**。屏幕高度不足 500dp（720p 一类）时，剧名预览从 27sp 收到 20sp、上下留白收窄，把竖向空间让给下面的货架。1080p（540dp）不变。
- **其它一个字没动**。0.9.58 的全部内容原样保留：切集不再多盖一层黑幕、预取不抢带宽、长关键词搜索、弹幕、遥控器焦点落点。

## 错乱是怎么来的

首页和列表页各有一套算海报高度的代码，只有首页那套是错的。

`HomeScreen.fitArtwork()` 拿的是卡片**量出来的宽度**：

```kotlin
val desired=((row.cards.first().view.width-dp(8))/TvStyle.POSTER_ASPECT).toInt()
```

`view.width` 在这一刻未必有值。首页的货架是分批到的：「接着看」先画出来，「热门发现」等热门数据回来以后才加进去。加进去的那一刻，卡片还没量过宽度，`view.width` 是 0 或者上一轮的旧值 —— 拿 0 算出来的高度是负数，海报就被压成了几像素高的一条线，剧名直接压在那条线上。

列表页（搜索、排行榜）那套 `MainActivity` 用的是**创建时就定下的布局宽**，所以那两页一直是对的 —— 同一个应用里两套算法，就差这一处。

这一版把首页也换成布局宽，和列表页用同一个来源：

```diff
- val desired=((row.cards.first().view.width-dp(8))/TvStyle.POSTER_ASPECT).toInt()
- val imageHeight=minOf(desired,(height-row.block.getChildAt(0).measuredHeight-textHeight-dp(8)).coerceAtLeast(dp(48)))
+ val cardWidth=(row.cards.first().view.layoutParams as LayoutParams).width
+ val desired=((cardWidth-dp(8))/TvStyle.POSTER_ASPECT).toInt()
+ val imageHeight=desired
```

第二行那处「按剩余高度缩水」也一起去掉了。1080p 的电视上两者算出来一样（剩下的高度比海报本身还高，缩水那一支从来不生效），所以电视的画面没有变化；有区别的是 720p 一类的矮屏：那里本来会把海报压成横条。

## 已知边界

- **这一轮没有重新装到投影仪上验证**。1080p 的电视上这次改动算出来的海报高度和改之前一模一样（剩下的高度本来就比海报高），预览区也不触发收紧（540dp ≥ 500dp），所以电视画面应当没有变化 —— 但这是算出来的，没有重新装包目视确认。
- **720p 一类的矮屏上，首页要往下滚**。一排货架（标题 + 海报 + 剧名 + 集数）比屏幕高，海报保持竖版比例的代价就是这一排放不下一屏。1080p 上没有这个现象。
- **系统字号仍然照着走**。这一版没有动字号逻辑：系统字号放大，剧名和海报占的地方就一起变大。矮屏上的预览块收紧了，货架卡片里的剧名还是两行。
- 投影仪上没有开 adb over network（5555 直接拒连），**logcat 读不到** —— 设备上出的问题只能靠人眼看，或者让 App 自己把状态送出来。
