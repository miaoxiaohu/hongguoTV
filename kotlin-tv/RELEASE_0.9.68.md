# Kotlin 0.9.68：播放接口偶尔拒答时，不再冤枉「这部剧只有 3 集」

<!-- notes -->
修好了「一直失败、反复自动重试」：站方播放接口有一半的请求会回空内容，以前这被当成「这一集不存在」，退到只有前 3 集的网页版，于是第 4 集起全挂。现在改成换一个设备身份重新签名再问，最多 6 次、4 秒以内。另外给地址加了排序，IPv4 先试、IPv6 兜底。
<!-- /notes -->
最低 Android 8.0 / API 26，versionCode 9068。单 APK，安装后联网使用，无需额外服务。沿用发布签名，可覆盖安装 0.9.67 并保留本机收藏、观看记录和设置。

## 这一版改了什么

- **播放接口空回不算「这集不存在」**。站方 `video_model/v1/` 大约一半的请求会回 HTTP 200 但 body 为空 —— 那是这一次被拒了，不是这一集没有资源。以前把它当成「没有」直接退到网页版（只有前 3 集），第 4 集起就报「该来源每部剧只提供前 3 集」，用户看到的是播放失败。现在换新设备身份重新签名再问，最多 6 次、总共不超过 4 秒。
- **「只有 3 集」不再被当成最终结论**。网页版 404 会说清「这一集没有资源」，signed 接口连续失败则报「播放接口返回空内容」，两件事不再混成一句。
- **地址顺序由应用说了算**。解析器返回的地址顺序决定电视走哪条路（IPv6 还是 IPv4）。现在按 IPv4 优先、IPv6 兜底重排。**一个地址都不删** —— `*.jspcdn.cn` 那批域名只有 AAAA 记录，删掉 IPv6 就等于让它解析不出来。OkHttp 连不上一个地址会换下一个，所以 IPv4 不通只是多等一次超时。

## 怎么量的

**空回率（同一请求、换不同身份重发）**

| 条件 | 空回率 |
|---|---|
| 换身份 | 46% |
| 不换身份 | 20% |
| h1 | 50% |
| h2 | 52% |
| 无延迟 | 54% |
| 延迟 250ms | 58% |
| 延迟 800ms | 50% |

加延迟打不散成簇（最长连续拒答都只有 3~4 次），所以**没有加退避延迟**，只加次数。单集平均需 1.75~2.33 次尝试，最坏 6 次。

|---|---|---|
| 改之前 | 20 | 10 |
| 改之后 | 28 | 2 |

## 验证记录

- `:core:test` 全绿（285 个），`:app:assembleRelease` 成功。
- 替身手机（Palm，192.168.1.30）装 0.9.68：ep51 首帧 **922 ms**、ep52（自动连播，复用预取）首帧 **398 ms**，全程 `Playback ready`，无 `Playback failure`、无 `Automatic playback recovery`。

- 电视（192.168.1.26）上验证时仍是 0.9.67：**这一版没推上去**。当时电视离线，推装服务（:10000）也不在线。

## 已知边界

- **IPv4 优先不等于纯 IPv4**。`*.jspcdn.cn` 那批域名只有 AAAA 记录，纯 IPv4 会更糟 —— 视频反而拉不到。IPv6 一直保留在后面兜底。
- **电视上的效果还没测**。Palm 的 IPv6 路由表本身是坏的（拿不到 AAAA），所以它本来就只走 IPv4，验证不了「优先 IPv4」在有 IPv6 的机器上的实际效果。要看真效果得等电视回来。
- 空回率没有降下去。接口还在拒，改的是「被拒了怎么办」——重问到成功为止。
