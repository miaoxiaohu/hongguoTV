# 弹幕密度与透明度（2026-11-01）

## 要解决什么

用户反馈：**「有时候弹幕太多太挡屏幕」**。

实测数据（2026-11-01，探针量的一集）：

| 指标 | 值 |
|---|---|
| 15 分钟弹幕总数 | 649 条（约 43 条/分钟） |
| 最密的 10 秒 | 153 条（≈15 条/秒） |
| 同屏最高 | 36 条 |
| AUTO 模式轨道数 | 7 行（720 高 → 字号 26px、行高 38px、上半屏 42%） |

结论：**挡屏幕的是条数，不是叠字**。36 条铺在 7 行里，屏幕上就是一片白字。

## 决定

用户拍板：

1. **限密度 + 透明度，两手都要**
2. 上限给成**固定档位**（少/中/多），不是自动算
3. 超限时**最多晚飘 2 秒，超了就丢**（不无限排队）
4. 默认值：**密度=中（12 条）、透明度=半透明**

## 实现

### core/DanmakuStyle.kt

- `DanmakuDensity`：少=6 / 中=12 / 多=24（`maxOnScreen`）
- `DanmakuAlpha`：不透明(255/220) / 半透明(165/200) / 淡(105/160)，数字是「填充 alpha / 描边 alpha」
  - 描边（黑边）始终比填充更实：亮画面上白字全靠那道黑边才看得清

### core/Danmaku.kt —— `DanmakuTimeline`

构造参数加 `maxOnScreen`（默认 `DanmakuDensity.MEDIUM`）。排布时在分轨道之外做**准入**：

```
want = 弹幕原本的入场时间
at = want
while (at - want <= 2000) {
    alive = 入场时间落在 (at-8000, at] 里的已放行弹幕数
    if (alive < maxOnScreen) → 放行，轨道照旧分配
    else → at = 最早离场那条的离场时刻，继续等
}
放不下 → 丢弃
```

要点：

- **被延后的弹幕要改入场时间**（`item.copy(enterAtMs=at)`）。不改的话它一露面就摆在画面中间 —— 那正是刚修好的「凭空冒出来」毛病。
- 延后上限 2 秒（`MAX_DELAY_MS`）。等一条弹幕走完要 8 秒，所以「等位置」几乎总是超时不候 → 爆发时大部分超限弹幕是**丢**的，不是排队的。
- `placed` 最后按最终入场时间重排（`visibleAt` 的二分依赖升序）。

### 持久化

- `BackupSettings` 加 `danmakuDensity` / `danmakuAlpha`；`json()` 写出、`decode` 读入。
- 旧备份里没有这两个字段 → 按当前默认（中 / 半透明）算，**备份不该让人丢设置**。
- `LibraryDisk.decode` 同样按默认值兜底。
- `Library.kt` 加两个属性 + `restore` 时回写磁盘（老坑：内存改了磁盘没改，下次启动又变回去）。

### app

- `DanmakuOverlay.setStyle(size, rows, density, alpha)`：密度变了要重排（哪些弹幕该丢、哪些该晚飘都要重算）。
- `DanmakuOverlay` 保留 `source`（原始弹幕全量）：重排要从全量重来，不能从「已经排好的」重来 —— 用户把密度调高时被丢掉的那些该回来。
- 设置页加「弹幕数量」「弹幕透明度」两行；播放中菜单同样加两项。

## 单测

`core/src/test/kotlin/com/hongguotv/core/DanmakuDensityTest.kt`：

- 同屏条数任何时刻都不超上限（36 条涌进来，上限 12 → 只放行 12）
- 弹幕不多时一条不少、一根手指都不动
- 满员时晚点飘进来（且从右边飞进来，elapsed=0）
- 等不到位置就丢（等 8 秒太久的丢）
- 延后上限 2 秒的边界
- 旧记录 / 旧备份的默认值兜底

## 已知取舍

- 上限 12 条 = 持续速率约 1.5 条/秒。实测平均 0.72 条/秒没问题；爆发段（15 条/秒）会丢掉大部分。
  想少丢就把密度调到「多」（24 条）。
- 「弹幕行数」（轨道数）和「弹幕数量」（条数上限）是两个独立旋钮：行数是画面上留几行给弹幕，数量是这几行里同时最多飘几条。

结论：不限上限时同屏最高 **26~29 条**；默认「中(12)」在最密的窗口会**丢掉约一半**（89 条留 48）；
「多(24)」几乎不丢（留 86~90）。**默认档位是否维持「中」留给用户拍板。**

### 实机（Palm，0.9.74 / versionCode 9074 正式包，无探针）

- 设置页左列出现「弹幕数量 · 中」「弹幕透明度 · 半透明」两行，默认值正确。
- 「弹幕数量」选择器：三档 `少 · 同屏 6 条` / `中 · 同屏 12 条` / `多 · 同屏 24 条`。
- 「弹幕透明度」选择器：三档 `不透明` / `半透明` / `淡`。
- 逐档切换并回读磁盘（SharedPreferences `native-library-v1`）：
  `danmakuDensity=LOW` → `danmakuAlpha=SOLID` → `danmakuAlpha=LIGHT` → 恢复 `MEDIUM`/`HALF`，
  每次都真实落盘。
- 播放中 HUD：更多面板 → 播放设置 → 往下滚到「弹幕数量」→ 打开的仍是三档同屏条数选择器。
- 播放画面确认弹幕在飘（实机截图可见滚动的白字弹幕）。
- 收尾：`am force-stop com.hongguotv.nativeapp`，设备上 `/sdcard/_*.png` 临时截图已删。
